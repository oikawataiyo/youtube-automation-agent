## Summary
NEEDS REVISION — autopilot の回帰防止、Reddit APIの商用利用可否、チャンネル別OAuth、収益化ポリシー適合について実行可能かつ測定可能な条件が不足しています。

## Issues
- Phase 0の検証が弱いです。移動前後の同一入力に対し、生成job、公開日時、動画ID、サムネイル、dry-run結果が一致する回帰テストと、旧パス参照の全件検査が必要です。
- `tokens.json` の単純複製ではブランドチャンネルを分離できません。各OAuthフローで対象YouTube channel IDを取得・保存し、設定したchannel IDとの不一致時はuploadを拒否する必要があります。
- credential、refresh token、`.env` の保存場所、Git除外、失効・再認証、権限不足時の挙動が未定義です。
- Reddit APIの商用利用可否が「要確認」のままPhase 1へ進む構成です。利用規約、収益化用途、保存期間、削除済み投稿への対応、表示・帰属要件を確認し、利用不可なら代替ソースへ切り替えるゲートが必要です。
- 「2026/7 の inauthentic content ポリシー」という前提の出典と発効日が明示されていません。最新のYouTube公式ポリシーを確認し、要求事項を受入基準へ落とす必要があります。
- 「付加価値型」だけでは収益化適合を測定できません。引用率上限、独自解説量、複数ソース利用、事実確認、人間レビュー、重複動画検出などの公開ゲートが必要です。
- Phase 6が遅すぎます。ブランド、音声、色、レイアウト、サムネイル規則はPhase 4と5の入力なので、少なくとも暫定brand specをPhase 3以前に確定すべきです。
- `threads.json` と `segments.json` の具体的なスキーマ、バージョン、必須項目、引用元URL・作者・取得日時が未定義です。後続工程との契約が成立していません。
- collectionの失敗モードが不足しています。rate limit、期限切れtoken、削除・編集済み投稿、NSFW、個人情報、重複、コメント取得失敗、部分成功、再実行時の冪等性を定義してください。
- 金融コンテンツとして、誤情報・相場操縦的投稿・銘柄宣伝への対策、根拠確認、免責表示、公開前レビューが欠けています。
- Phase 5の受入条件がなく、誤チャンネル投稿を防げません。dry-run、channel ID確認、非公開テスト投稿、予約確認後に本番公開する段階的ゲートが必要です。

## Suggestions
- Phase 0開始前に現行autopilotのgolden fixtureと実行ログを保存し、移動後に自動比較してください。
- `channels.json` に期待する`youtubeChannelId`、timezone、privacy default、credential profileを追加し、起動時にスキーマ検証してください。
- `--channel`省略時の暗黙autopilotは移行期間限定とし、警告を表示すると誤投稿リスクを下げられます。
- Phase順を `0 → 1利用可否ゲート → 2 → 暫定6 → 3-4 → 0.5 → 5` に変更してください。
- 各Phaseに「成果物、実行コマンド、成功条件、失敗時の復旧方法」を追加してください。
- `reddit_for_invester` が意図した綴りか確認してください。一般的な英語表記は `investor` です。
